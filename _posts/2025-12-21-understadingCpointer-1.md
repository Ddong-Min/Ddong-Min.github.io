## int* vs int (*)[3] 무엇이 다른것인가?

C언어 교재를 읽다가 문득 궁금증이 생겼다.

교재에서는 `int matrix[3]`와 같은 배열이 있을 때:
1. **`matrix`**만 쓰면 배열의 이름이므로 첫 번째 요소를 가리키는 **`int*`** 타입을 가지고,
2. **`&matrix`**라고 쓰면 배열 전체의 주소를 나타내므로 **`int (*)[3]`** 타입을 가진다고 설명한다.

여기서 의문이 들었다. **"배열 전체 주소를 가리킨다는 것이, 첫 번째 요소만 가리키는 것과 도대체 값적으로 뭐가 다르다는 말인가?"**

어차피 시작 주소는 같을 텐데, '전체 주소를 가리킨다'는 의미가 실제 메모리나 코드 레벨에서 어떻게 동작하는지 눈으로 확인해보고 싶어 실험을 진행했다.

---

### 실험 설계 1 : 주소값과 타입 크기(Size) 확인

가장 확실한 방법은 **주소값 자체**와, 그 주소를 **역참조(Dereferencing) 했을 때의 크기(Size)**를 비교해보는 것이라 생각했다.

* **비교 대상**: `matrix` vs `&matrix`
* **확인 요소**:
    1.  출력되는 포인터의 주소값이 동일한가?
    2.  해당 포인터를 역참조(`*`) 했을 때 인식하는 크기(`sizeof`)가 다른가?

#### 작성 코드

```c
#include <stdio.h>

void test1_basic(){
    int matrix[3] = {1, 2, 3};
    
    // 1. 주소값 비교
    printf("matrix  주소 : %p \n", matrix);
    printf("&matrix 주소 : %p \n", &matrix);
    
    // 2. 역참조 후 크기 비교
    printf("sizeof(*matrix)   : %zu \n", sizeof(*matrix));
    printf("sizeof(*(&matrix)): %zu \n", sizeof(*(&matrix)));
}

```

#### 실험 1 결과

```text
matrix  주소 : 000000051d1ffeb4 
&matrix 주소 : 000000051d1ffeb4 
sizeof(*matrix)   : 4 
sizeof(*(&matrix)): 12

```

### 결과 해석

실험 결과를 통해 모호했던 개념이 확실해졌다.

#### 1. 주소값은 같다

출력 결과를 보면 `matrix`와 `&matrix`는 `000000051d1ffeb4`로 **완전히 동일한 주소값**을 출력한다. 둘 다 메모리 상에서 배열이 시작되는 '첫 번째 요소의 주소'를 가리키고 있기 때문이다.

#### 2. 하지만 '타입 정체성'이 다르다 (핵심)

주소값은 같지만, 컴파일러가 이 주소를 바라보는 **관점(Type)**이 다르다는 것이 `sizeof`를 통해 증명되었다.

* **`*matrix` (4 byte)**:
* 배열의 이름 `matrix`는 `int*` (첫 번째 요소의 주소)로 취급된다.
* 따라서 역참조(`*`)를 하면 딱 `int` 하나(`matrix[0]`)만 가져오므로 크기는 **4바이트**다.


* **`*(&matrix)` (12 byte)**:
* `&matrix`는 `int (*)[3]` (크기가 3인 정수 배열 전체의 포인터) 타입을 가진다.
* "나는 그냥 숫자 하나가 아니라, 배열 덩어리다!"라는 정체성을 유지하고 있다.
* 따라서 역참조(`*`)를 하면 배열 전체(`int` 3개)를 인식하므로 크기는 3 × 4 = **12바이트**가 된다.

---

### 실험 설계 2 : 포인터 연산 (Pointer Arithmetic)

위 실험을 통해 **"타입이 인식하는 크기가 다르다"**는 것을 알았다. 그렇다면 **포인터에 `+1`을 했을 때 점프하는 거리(보폭)**도 달라야 한다.

그래서 두 번째 실험을 설계했다.

* **가설**: `matrix + 1`은 `int` 크기(4)만큼 증가할 것이고, `&matrix + 1`은 배열 전체 크기(12)만큼 증가할 것이다.

#### 작성 코드 (추가)

```c
void test1_arithmetic(){
    int matrix[3] = {1, 2, 3};
    
    printf("Original Addr       : %p \n", matrix);
    printf("--------------------------------------\n");
    
    // int* 타입의 연산
    printf("matrix + 1          : %p \n", matrix + 1); 
    
    // int (*)[3] 타입의 연산
    printf("&matrix + 1         : %p \n", &matrix + 1);
}

int main() {
    test1_basic();
    printf("\n");
    test1_arithmetic();
    return 0;
}

```

### 실험 2 결과

```text
Original Addr       : 000000051d1ffeb4 
--------------------------------------
matrix + 1          : 000000051d1ffeb8 
&matrix + 1         : 000000051d1ffec0 

```

---

### 결과 해석

실험 결과를 16진수로 분석해보면 명확해진다.

1. **`matrix + 1`**:
* `...eb8` - `...eb4` = **4 (bytes)** 차이.
* `int*` 타입이므로 **다음 원소(`matrix[1]`)**로 이동했다.


2. **`&matrix + 1`**:
* `...ec0` - `...eb4` = **12 (bytes)** 차이. (C0(192) - B4(180) = 12)
* `int (*)[3]` 타입이므로 **배열 전체(덩어리)를 건너뛰어** 그 다음 메모리 블록으로 이동했다.


**[요약]**
`int*`와 `int (*)[3]`는 가리키는 **시작 주소는 같지만**, **보폭(Stride)**이 다르다.

* `matrix`: 낱개 단위(Element-wise) 접근
* `&matrix`: 덩어리 단위(Block-wise) 접근
